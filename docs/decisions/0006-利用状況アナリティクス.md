# 0006. 利用状況アナリティクスを Firebase Analytics で導入（内容は送らない・オプトアウト可）

- Status: Accepted
- Date: 2026-09-23

## Context
v1.1 まで計測ゼロで、「どれくらい使われ、続き、どの機能が効き、KPI（"やった"に変わった数）が
動いているか」を知る手段が App Store Connect の粗い数字しかなかった。改善を回すには
DAU/継続/機能別利用/ヘビーユーザー分布/達成数が要る。制約は **無料**であること。

候補：TelemetryDeck（プライバシー第一・Apple 特化だが新規は無料 5 万シグナル/月）、PostHog（無料 100 万/月・汎用）、
Aptabase（無料 2 万/月）、Firebase Analytics（無料・無制限・Google）。
将来 AdMob を入れる可能性があり、その場合 Google 系 SDK はどのみち入る。

一方で設計原則§8（オンデバイス・外部送信しない）と、公開済みのプライバシーポリシー／App Privacy
「データを収集しません」との整合が問題になる。

## Decision
- **Firebase Analytics** を採用（無料枠の心配がなく、AdMob と同一プロジェクトで収益分析まで繋がる）。
- **原則§8 の線引きを明文化**：外に出さないのは「ユーザーの内容（タイトル/メモ/URL/タグ名/名前）」と「推論」。
  匿名の**利用イベント**（固定語彙・件数・バケット）は送ってよい。原則§8「実装での守り方」にこの線引きを参照として追記
  （原則の変更ではなく明文化）。
- 初回オンボーディング最終ページに一文の告知（「匿名の利用統計を送ります／設定でオフ可」）。同意ダイアログは出さない（§1）。
- **設定でオプトアウト可**（`Tweaks.analyticsEnabled`、既定 ON）。Apple のルール上、トラッキングでない
  利用分析に同意ダイアログは不要だが、切れる手段は必ず置く（原則§6・§8 の精神）。
- SDK は本体ターゲットのみ。拡張は App Group キュー経由。入口は `Analytics.swift` 1ファイル（差し替え可能）。
- DEBUG は送らない（`ANALYTICS_DEBUG=1` で明示したときだけ）。
- IDFA/ATT は使わない。IDFV 収集・広告パーソナライズ信号もオフ（`Info.plist`）。

## Consequences
- App Privacy は「データを収集しません」→「利用状況データ（プロダクトの操作）／ユーザーに紐付けない／
  トラッキングなし」＋ Firebase SDK が申告する識別子へ変更。公開プライバシーポリシー §1/§6 と
  ストア説明文の「分析は一切ありません」も改訂（[app-store-metadata](../workflows/app-store-metadata.md)）。
- 「一切通信しない」とはもともと謳っていない（リンク取得のため）。表現は「推論はオンデバイス・内容は送らない」。
- 外部依存ゼロではなくなる：SPM `firebase-ios-sdk` が入り、初回ビルドが数分伸びる。高速型チェックは
  `ANALYTICS_FIREBASE` 条件のおかげで従来どおり動く。
- イベント名は履歴の鍵。変えるときは新 ADR。語彙は [architecture/analytics.md](../architecture/analytics.md) が正典。
- AdMob 導入は別の判断（買い切り Pro の [ADR 0005](0005-v1無料とPro無効フラグ.md) と製品性格に関わる）。
  その際は ATT/UMP が必要になり、本 ADR の「IDFA を使わない」を改める新 ADR が要る。
